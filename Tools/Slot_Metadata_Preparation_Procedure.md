# STM32F407 FOTA Tools

This folder contains host-side Python utilities and the procedure used to prepare and program firmware metadata for the STM32F407 Secure Boot project.

The current procedure uses:

* Cygwin Terminal for Python and file preparation
* STM32CubeIDE GDB for flash programming and verification
* ST-LINK GDB Server for target access

STM32CubeProgrammer is not currently available on the development system.

## 3. Check Firmware Build Outputs

The firmware ELF files are generated by STM32CubeIDE:

```text
Bootloader/Debug/Secure_Boot.elf
Firmware_Slot_A/Debug/Firmware_Slot_A.elf
Firmware_Slot_B/Debug/Firmware_Slot_B.elf
```

Initially, no `.bin` files were present.

CubeIDE was configured to generate the firmware binary after build.
In Properties -> C/C++ Build -> Settings -> Post-build steps → Command, add:
```bash
arm-none-eabi-objcopy -O binary "${BuildArtifactFileName}" "${BuildArtifactFileBaseName}.bin"
```
The Slot A binary is now available at:

```text
Firmware_Slot_A/Debug/Firmware_Slot_A.bin
```

The Slot B binary is generated similarly:

```text
Firmware_Slot_B/Debug/Firmware_Slot_B.bin
```

To check for binary files from Cygwin:

```bash
find . -type f -name "*.bin"
```

## 4. Python Slot Metadata Generator

The host-side metadata tool is:

```text
Tools/
└── prepare_slot_metadata.py
```

The tool is used to create a complete metadata-sector binary for Slot A or Slot B.

It performs the following steps:

```text
Firmware .bin
      ↓
Read firmware
      ↓
Calculate image size
      ↓
Calculate SHA-256
      ↓
Create firmware metadata
      ↓
Add sequence number
      ↓
Add update state
      ↓
Calculate metadata CRC
      ↓
Add commit marker
      ↓
Create 16 KB metadata-sector binary
```

The Python tool does not directly access STM32 Flash.

Metadata Size
```text
Offset  Size   Field
0x00    4      sequence
0x04    4      magic
0x08    4      image_size
0x0C    4      version
0x10    32     SHA-256
0x30    4      update_state
0x34    4      metadata_crc
0x38    4      commit_marker
```

---

### Generate Slot A Metadata

From the repository root, run:

```bash
python Tools/prepare_slot_metadata.py \
    --slot A \
    --firmware "./Firmware_Slot_A/Debug/Firmware_Slot_A.bin" \
    --elf "./Firmware_Slot_A/Debug/Firmware_Slot_A.elf" \
    --objcopy "/cygdrive/c/ST/STM32CubeIDE_1.19.0/STM32CubeIDE/plugins/com.st.stm32cube.ide.mcu.externaltools.gnu-tools-for-stm32.13.3.rel1.win32_1.0.0.202411081344/tools/bin/arm-none-eabi-objcopy.exe" \
    --version 1 \
    --sequence 1 \
    --state CONFIRMED \
    --output "./Tools/Test_Data/Slot_A/Slot_A_Metadata.bin" \
    --flash-image-output "./Tools/Test_Data/Slot_A/Firmware_Slot_A_FlashReference.bin"
```

## 5. Python Staging Metadata Generator

The host-side staging metadata tool is:

```text
Tools/
└── prepare_staging_metadata.py
```

The tool is used to create a complete metadata-sector binary for a firmware image stored in the FOTA download/staging area.

Unlike `prepare_slot_metadata.py`, this tool calculates the SHA-256 directly from the raw firmware `.bin` that is written to the staging area.

It performs the following steps:

```text
Firmware_Staging.bin
      ↓
Read firmware
      ↓
Calculate image size
      ↓
Calculate SHA-256
      ↓
Create firmware metadata
      ↓
Add sequence number
      ↓
Add update state
      ↓
Calculate metadata CRC
      ↓
Add commit marker
      ↓
Create 16 KB metadata-sector binary
```

The Python tool does not directly access STM32 Flash.

### Metadata Size

```text
Offset  Size   Field
0x00    4      sequence
0x04    4      magic
0x08    4      image_size
0x0C    4      version
0x10    32     SHA-256
0x30    4      update_state
0x34    4      metadata_crc
0x38    4      commit_marker
```

---

## 6. Save Metadata in respective sector
### a. Erase sector
Before writing the new metadata, Sector 2 must be erased because Flash cannot normally change a programmed `0` back to `1`.
```gdb
call FlashStorage_EraseSector(2, 2)
```
Using the bootloader flash erase functionality, Sector 2 was erased.

Verify the sector using:

```gdb
x/12wx 0x08008000
```

Expected:

```text
0xffffffff
```

Observed:

```text
0x8008000:  0xffffffff  0xffffffff  0xffffffff  0xffffffff
0x8008010:  0xffffffff  0xffffffff  0xffffffff  0xffffffff
0x8008020:  0xffffffff  0xffffffff  0xffffffff  0xffffffff
```
This confirmed that Sector 2 was erased.

### b. Save Generated file in RAM
The generated file first save in RAM since directly saving in Flash is prohibited:

```gdb
restore ../Tools/Test_Data/Slot_A/Slot_A_Metadata.bin binary 0x20010000
```
Verify the RAM using:

```gdb

```

Expected:

```text

0x20010020: 0x2897083e  0x601c5c31  0xbcdc570e  0xec59ac77
0x20010030: 0x45d978df  0xa5a55a5a  ....

```text

## 7. Append into Metadata Sector 

call:
```gdb
call Metadata_WriteRecord(0x08008000, 0x0800C000, FLASH_SECTOR_2, FLASH_VOLTAGE_RANGE_2, (firmware_metadata_t *)0x20010000)
```
However, GDB may not recognize FLASH_SECTOR_2 or FLASH_VOLTAGE_RANGE_2, because those are normally preprocessor macros. In that case use their numeric values or inspect the definitions in your code.
